# Marionette — Talking-Head Video Diffusion (SD 2.1 UNet)

A latent video diffusion model for talking-head generation. Given a reference
portrait, a per-frame FLAME expression map (either ground-truth rasterized
from tracked FLAME fits, generated by the Marigold module in
[`../marigold_training/`](../marigold_training/), or — for ablation — the raw
driving video itself at latent resolution), and audio, the model generates
temporally coherent talking-head video. Uses Stable Diffusion 2.1's UNet
extended with 3D spatiotemporal attention.

## Architecture Overview

The model operates in SD 2.1's VAE latent space (4 channels, 8× spatial
downsampling). It generates T=16 consecutive frames per forward pass via a
UNet whose 2D self-attention is replaced with 3D spatiotemporal attention —
convolutions remain per-frame, only attention connects frames temporally.

Reference and generated frames are concatenated along the time axis
`[1 ref | 15 generated]`. The 3D attention operates across all 16 frames,
allowing generated frames to attend to the reference for identity preservation.
For reference frames (`ref_mask=1`), the UNet bypasses learned prediction and
outputs the known noise residual `x - z_input`, so the reference passes
through unchanged while still participating in attention. Loss is masked to
non-reference frames only.

## Conditioning Signals

| Signal | Mechanism | Channels/Dim | Description |
|---|---|---|---|
| **Expression map** | Spatial addition to UNet first feature map | 46ch / 4ch / 1ch (config) | FLAME rasterization (GT), pre-cached Marigold predictions, or downsampled driver video |
| **Audio** | Cross-attention in every transformer block (optional) | 1024 (wav2vec2-base → learned linear) | Per-frame audio tokens from ±2 context frames. Cleanly ablatable: `use_audio_context=false` + `audio_encoder_config=null` |
| **Head pose** | Added to the timestep embedding (optional) | `model_channels × 4` | 6DRepNet backbone (frozen) → sinusoidal encoding → learned MLP. Per-frame head orientation. Turn on with `overlays/pose/on.yaml`. |
| **Reference frame** | Identity passthrough via `z_input` + `ref_mask` | 4ch VAE latent | GT latent for frame 0, zeroed for generated frames |

The expression map conditioning is projected to `model_channels` (320) via a
learned linear layer and added to the UNet's first feature map. Audio tokens
serve as keys/values in cross-attention blocks. The pose embedding is added
to the timestep embedding, so head pose modulates every ResBlock and
transformer block through the existing `emb` pathway.

### Expression-map channel layout

- **46ch** (full, base default): 42ch Fourier positional encoding of rasterized
  3D vertex positions + 3ch expression deformation + 1ch ref_mask.
- **4ch** (`overlays/conditioning/deform_only.yaml`): 3ch deformation + 1ch ref_mask.
  Used when comparing against the 3ch-only Marigold and driving-video sources.
- **1ch** (`overlays/conditioning/no_expr.yaml`): ref_mask only.

## Expression-Weighted Loss

The diffusion loss is weighted per-pixel by expression deformation magnitude.
Pixels where the face is actively deforming (mouth opening, brow raising)
receive higher loss weight, forcing the denoiser to prioritize face dynamics:

```
weight = 1.0 + alpha * normalize(deformation_magnitude)
loss   = weighted_mean(MSE(noise_pred, noise) * weight)
```

Static regions (background, forehead) keep baseline weight 1.0 — they're never
suppressed, only active regions are amplified. `expr_weight_alpha=0` gives
uniform loss (base default). `expr_weight_alpha=5.0` is the standard weighted
setting (`overlays/loss/weighted.yaml`).

The deformation magnitudes come from `expr_weight_map` — always computed from
the full expression field, even in ablation configs where the UNet doesn't see
it as spatial conditioning.

## Config System

Configs are composed from a single base + overlays. No duplicated concrete
configs exist. See [`../experiments/README.md`](../experiments/README.md) for
the experiment-side overlay composition pattern.

```
marionette/configs/
├── base.yaml                         # every default value (used by every experiment)
└── overlays/
    ├── conditioning/
    │   ├── deform_only.yaml          # → 4ch UNet conditioning
    │   └── no_expr.yaml              # → 1ch UNet conditioning
    ├── loss/
    │   └── weighted.yaml             # α=5.0
    ├── audio/
    │   └── off.yaml                  # disable wav2vec2 cross-attention
    ├── expr_source/
    │   ├── marigold.yaml             # Marigold-cached deformation mp4s
    │   └── driving_video.yaml        # raw driving frames at latent res
    └── pose/
        └── on.yaml                   # enable 6DRepNet head pose embedding
```

Resolution is done by `marionette.config_utils.load_experiment_config(path)`,
which merges `base + overlays + inline overrides` and returns a DictConfig.
`marionette.train.run_training(cfg, ...)` is the programmatic training entry
point — experiment scripts import it directly instead of shelling out.

## Training

Experiment scripts under [`../experiments/`](../experiments/) are the
recommended way to launch training — they handle clip filtering, output
directories, and symlinks automatically. Example:

```bash
conda activate marionette
PYTHONPATH=. python experiments/ablate_expr_source/run.py marigold --gpus 0 1 2 3
```

For ad-hoc runs directly against any experiment config:

```bash
PYTHONPATH=. python marionette/train.py \
    --config experiments/ablate_expr_source/configs/marigold.yaml \
    --gpus 0 1 2 3
```

The dataset splits each clip into non-overlapping 16-frame windows
(deterministic). DDP uses `find_unused_parameters=True` (frozen VAE /
conditioning module parameters don't contribute to the training loss).
Timestamped run directories carry `config_resolved.yaml` for reproducibility,
TensorBoard logs, and visualization grids (GT / expression map / generated)
produced by the visualization callback. The vis callback runs only on rank 0
and is wrapped in a `torch.distributed.barrier()` pair so other ranks wait
for it to finish instead of racing ahead into collectives rank 0 can't
participate in (earlier versions triggered NCCL watchdog timeouts).

## Cross-Identity Evaluation

Training uses same-identity pairing (paired ground truth is required for the
denoising objective). Evaluation switches to **cross-identity driving** by
default (`val_dataset.params.cross_identity_driving: true` in `base.yaml`) so
the model is judged on its ability to follow external expression cues rather
than reproducing signals trivially extracted from the target itself.

In cross-identity mode, `TalkingHeadDataset` builds a seeded permutation over
the val clips and, for each target sample:

- **Target** provides: the reference frame (frame 0) and the reconstruction
  target (`jpg`).
- **Driver** (a different clip chosen by the permutation) provides: the
  expression signal (FLAME verts / Marigold deformation / driving video), and
  the **audio**.

The permutation is built to minimise same-identity pairings and self-pairings
(greedy assignment processing identities with most clips first; achieves the
theoretical minimum for any given val-set identity distribution).

> **Note:** val MSE loss under cross-identity is a weak signal (no paired
> ground truth exists for "identity A doing identity B's expression"). Use
> visualizations and downstream metrics (lip-sync, FID) for real evaluation.
> Checkpoint selection by `val/loss_simple_ema` still works but measures
> something different than training loss.

## Inference

```bash
PYTHONPATH=. python marionette/generate.py \
    --checkpoint outputs/ablate_expr_source/marigold/run_YYYYMMDD/th-best.ckpt \
    --config experiments/ablate_expr_source/configs/marigold.yaml \
    --ref_data /path/to/subject/ \
    --driving_fit /path/to/driving/fit.npz \
    --audio /path/to/audio.wav
```

Identity (shape, camera, appearance) from the reference subject, expressions
(`expr`, `eye_rot`) from the driving video, audio from the driving audio file.
The `THSampler` implements sliding-window DDIM for long video generation.

